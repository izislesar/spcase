## 1. Концепция и Визуальный Стиль

Визуальный язык платформы вдохновлен эстетикой сайта [redsnapper.net](https://www.redsnapper.net/home) — чистый редакционный поп-арт / Light Neo-Brutalism.

### Ключевые принципы дизайна:

* **Интерфейсный минимализм:** Контрастные границы, отсутствие градиентов и тяжелых теней, крупные типографические акценты, сетка и четкие функциональные зоны.
* **Микроинтерактивность:** Ощутимый фидбек на действия пользователя — при наведении и клике элементы слегка смещаются, меняют толщину границ или цвет фона (эффект нажатия на физическую кнопку).
* **Сканнируемость (Scannability):** Понимание состояния пользователя (`NO_TEAM`, `IN_TEAM`, `CAPTAIN`) за 1 секунду благодаря бейджам-чипам и акцентным фоновым карточкам.

## 2. Цветовая Палитра и Цветовые Ограничения

### Цветовая схема

```css
:root {
  /* Основные тона (RedSnapper Style) */
  --bg-primary: #FDFBF7;        /* Молочный айвори (основной фон страницы) */
  --bg-card: #FFFFFF;           /* Чистый белый (фон карточек и контейнеров) */
  --text-main: #0B1B3D;         /* Глубокий темный (текст, границы, заголовки) */
  
  /* Акценты */
  --accent-yellow: #F9AB06;     /* Горчично-оранжевый / Ярко-желтый (кнопки, активные фокусы) */
  --accent-red: #FF4D4D;        /* Малиново-красный (деструктивные действия: Kick, Disband, Hard Lock) */
  --accent-green: #20C997;      /* Мятно-зеленый (успех, готовый статус команды) */
  
  /* Границы и структуры */
  --border-width: 2px;
  --border-color: #0B1B3D;
  --box-shadow-brutal: 4px 4px 0px #0B1B3D;
  --box-shadow-press: 1px 1px 0px #0B1B3D;
}

```

### 🚫 Строгие цветовые ограничения

Во избежание визуального диссонанса и политики **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНЫ**:

1. Прямые сочетания **голубого и желтого** (`#0057B7` + `#FFD700`).
2. Сочетания **белого, синего и красного** в единых блоках/триадах.

## 3. Компоненты и UI-Спецификация

### 3.1. Кнопки (Buttons)

* **Стандартная кнопка:** Фон `--accent-yellow`, сплошная граница `2px solid #0B1B3D`, жесткая тень `box-shadow: 4px 4px 0px #0B1B3D`.
* **Hover / Active State:** При наведении тень смещается, при клике (`:active`) кнопка сдвигается на `3px 3px`, а тень уменьшается до `1px 1px`.
* **Opne/Secondary Button:** Фон `--bg-card`, граница `2px solid #0B1B3D`, черные буквы.
* **Destructive Button:** Фон `--accent-red`, белый или глубокий темный текст (для кнопок «Расформировать», «Кикнуть»).

### 3.2. Статус-Бейджи (Status Badges / Chips)

Крупные контрастные метки в шапке и карточке профиля:

* `В поиске ⏳` — Фон `--accent-yellow`, черная граница (состав < 2 человек).
* `Команда готова 🟢` — Фон `--accent-green`, черная граница (состав 2–4 человека).
* `Решение сдано 🚀` — Фон `--text-main`, текст `--bg-primary` (ссылка валидирована и сохранена).

### 3.3. Аккордеон (FAQ Accordion)

* Плиточный список вопросов с черными границами `2px`.
* При клике на вопрос плашка плавно раскрывается вниз, стрелка-иконка поворачивается на $180^\circ$.
* Открытый ответ подсвечивается легким фоновым оттенком `#F4EFE6`.

## 4. Страницы и Публичный/Закрытый Flow

### 4.1. Главная страница (`/`)

* **Hero-блок:** Крупный заголовок кейс-чемпионата, таймер обратного отсчета (Countdown) строго **до окончания регистрации**.
* **Экран выбора (для залогиненного участника без команды):**
* Две доминирующие карточки-кнопки:
1. **«У меня есть команда»** → Открывает модалку / форму создания команды или ввода 8-значного инвайт-кода.
2. **«У меня нет команды»** → Редирект на `/no-team`.





### 4.2. Страница «У меня нет команды» (`/no-team`)

* Понятная визуальная карточка с текстом-инструкцией.
* Крупная CTA-кнопка **«Перейти в Telegram-чат поиска команды»** (открывает внешнюю ссылку в новой вкладке `target="_blank"`).

### 4.3. Кабинет команды (`/team/my`)

* **Виджет инвайт-кода (Только для капитана/участников):**
* Крупный моноширинный код (например, `X8K2M9N7`).
* Кнопка **«Скопировать код»** (при клике меняет текст на *«Скопировано! ✓»* на 2 секунды).


* **Список участников:**
* Карточки членов команды с плашкой `Капитан` или кнопкой `[Кикнуть]` (только для капитана).
* Кнопки `[Выйти из команды]` (для участника) и `[Передать права капитана]` / `[Расформировать]` (для капитана).


* **Блок сдачи решения (Только для капитана):**
* Текстовое поле ввода ссылки на Яндекс.Диск / Google Drive.
* Статус-блок после сохранения: *«Ссылка успешно сохранена: [Открыть ссылку]»* + кнопка `[Заменить]`.



### 4.4. Таймлайн и Расписание (`/schedule`)

* Вертикальный степпер с таймингом этапов (Регистрация, Открытие, Чекпоинты, Дедлайн сдачи, Питчи).

### 4.5. Панель жюри (`/jury/teams`)

* Таблица с шириной $100\%$, контрастными сетчатыми границами.
* **Колонки:** `Название команды` | `Состав` | `Ссылка на решение` | `Оценка (Критерии)` | `Статус`.
* Поля ввода числовых баллов с моментальной автосохраняющей кнопкой `[Сохранить оценки]`.
* Фильтр/Чекбокс: *«Скрыть проверенные»*.

## 5. Техническая реализация и Взаимодействие с API

### 5.1. Авторизация и Сессия

* Фронтенд **НЕ хранит** JWT в `localStorage` или `sessionStorage`.
* Все запросы через `fetch` / `axios` / `HTMX` передают опцию `credentials: 'include'`.
* При получении HTTP `401 Unauthorized` происходит авто-редирект на форму `/login`.

### 5.2. Обработка ошибок и Валидация

* **Hard Lock (HTTP 403):** При попытке выполнить запрещенное действие за 1 час до дедлайна или после дедлайна сдачи отображается тост-уведомление / модалка цвета `--accent-red` с текстом: *"Время сдачи или изменения состава истекло!"*.
* **Формы:** Поле ввода ссылки валидируется на клиенте через регулярное выражение `^https?://.+` перед отправкой на бэкенд.
